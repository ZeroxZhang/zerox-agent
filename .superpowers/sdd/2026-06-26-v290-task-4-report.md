# v2.9.0 Task 4 Report - Format-Specific React Renderers

## Scope

Implemented Task 4 for v2.9.0 output rendering: assistant messages now render typed output parts through dedicated React components instead of flattening structured parts into markdown. User messages continue to use the existing local markdown renderer, and legacy assistant messages still flow through `outputPartsFromMessage()` as fallback text parts.

## Refactor Evidence

- Added `AnswerBlock` as the assistant output container and `EvidenceRail` as the compact evidence surface for citations, artifacts, file refs, approvals, and diagnostics.
- Added `OutputPartRenderer` with exhaustive switch coverage for all current `ChatOutputPart.type` cases: text, table, code, file_diff, command_output, tool_call, tool_result, file_ref, artifact, citation, approval_request, input_request, diagnostic, and ledger_event.
- Added semantic dedicated renderers:
  - `DataTableView` uses table/caption/thead/tbody semantics and fills missing row cells.
  - `CodeBlockView` uses figure/figcaption/pre/code for code and diffs.
  - `CommandOutputView` renders command, cwd, exit, elapsed, stdout, and stderr as terminal-style text blocks.
  - `JsonPreview` masks preview secrets with `maskPreviewSecrets()` and renders serialized text only.
  - `RunLedgerView` renders ledger status/title/detail/tool metadata.
- Kept raw model output out of `dangerouslySetInnerHTML` and avoided new dependencies.
