# Zerox Agent v3.9.0

本版本完成核心本地数据的 SQLite 权威收敛，并集中修复运行时、持久化、原生进程和凭据边界中的一致性问题。

## 主要更新

- SQLite 现在是正式运行时的默认存储权威。Goal、执行 checkpoint、Memory、Workspace、Multi-Agent Session、审核后的 Learning、Eval Candidate 和 promoted fixture 已从 JSON 权威迁入 `zerox.db`。
- 首次升级按数据域原子导入旧 JSON，并写入持久化 authority marker。损坏源、坏 Goal ledger 行、代际冲突或 canonical mismatch 会回滚当前域，不会留下半迁移状态。
- 离线迁移与 rollback 支持完整八域 round trip、幂等验证、更新代冲突拒绝、原子 staging 和逆序补偿。显式回滚到 JSON 后，后续切回 SQLite 会按 rollback marker 重新导入 JSON 权威。
- Goal 保留终态不可逆、验收证书校验、状态 CAS、Plan 版本 CAS 和 ledger publication exactly-once；runtime checkpoint 阻止终态复活。
- Memory 保留 embedding、hybrid RRF、reranking、maintenance、governance 和 session isolation；并发整表事务使用 expected-snapshot CAS。
- Workspace 与 Multi-Agent Session 保留稳定排序、幂等 child run 和角色映射；共享 session 表增加 Chat/Multi-Agent kind 隔离。
- Learning、Eval Candidate 和 promoted fixture 保留审核状态、复合 identity、CAS 竞争和同事务 promotion。
- Chat 搜索使用 trigram FTS 和有界短词候选，session list 与 transcript 使用 metadata/projection 和 cursor 分页。
- 原生 `rg`/Git 读取统一进入受限 process adapter，执行最小环境、只读 Seatbelt、无网络、AbortSignal 和进程树 drain；封堵 `rg --pre` 命令注入。
- MCP `env`/`headers` 不再进入 renderer、Goal 或 Plan；Tool Result metadata 缺失、损坏或 hash 不一致时 fail closed。
- Kernel 只在 durable settlement 完成后发布唯一 `run_end`；scheduler sweep、shutdown drain 和 rollback failure 均保持可见。

## 升级与恢复

正常启动会自动完成一次性逐域导入。需要离线验证时可运行：

```bash
node scripts/migrate-to-sqlite.mjs --configDir "<userData>/config" --verify
```

若 native SQLite 无法加载，默认 `sqlite`/`dual` 模式会拒绝启动，而不是静默写入旧 JSON 并分裂权威。

## macOS 安装说明

本次发布继续采用项目既有的 `legacy-adhoc` 非 Apple 公证兼容模式。应用包经过 ad-hoc codesign 校验，`latest-mac.yml` 使用项目独立 Ed25519 更新密钥签名。

只应对从本项目 GitHub Release 下载且你信任的文件移除 quarantine：

```bash
xattr -dr com.apple.quarantine ~/Downloads/"Zerox-Agent-3.9.0-arm64.dmg"
```

如果已经将应用拖入“应用程序”：

```bash
xattr -dr com.apple.quarantine "/Applications/Zerox Agent.app"
```

发布附件固定为 ZIP、DMG、两个 blockmap、`latest-mac.yml` 和 `latest-mac.yml.sig` 六个文件。
