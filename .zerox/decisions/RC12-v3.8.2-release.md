# RC12 Decision: Zerox Agent v3.8.2 Release

Status: Accepted

Date: 2026-08-14

## Context

Zerox Agent v3.8.1 is already published and its annotated tag resolves to
commit `4e86f1efbf0d7545383c286102992338d621dd37`. Current `main` contains the
verified runtime convergence, review hardening, dependency remediation, and
stress-gate commits, so reusing or moving v3.8.1 would violate immutable release
history.

The local machine does not hold the update-signing private key. The repository
already has a tag-triggered GitHub Actions release workflow that materializes
the key from repository secrets, builds the compatibility package, signs the
update manifest, runs release preflight, and publishes six verified assets.

## Decision

- Release current `main` as patch version 3.8.2.
- Preserve v3.8.1 and every existing release asset unchanged.
- Update package metadata, README current-release links, release tests, and a
  dedicated `v3.8.2.md` release note.
- Add `npm run stress:runtime` to the tagged release verification job.
- Create one clean release-preparation commit, then an annotated `v3.8.2` tag
  resolving exactly to that commit.
- Push the tag and let the existing GitHub Actions workflow build, sign,
  preflight, and publish.
- Close P83/RC12 only after the workflow succeeds and the public Release has
  exactly the expected six assets.

## Invariants

1. No existing tag is moved, deleted, or overwritten.
2. Package, lockfile, README, notes, asset names, and tag all use 3.8.2.
3. The release tag resolves to the clean, verified release-preparation commit.
4. Stress, full tests, build, evals, audit, harness, and program checks pass
   before tag creation.
5. GitHub Actions uses the tracked `legacy-adhoc` compatibility path and
   Ed25519 update-manifest signing.
6. The published Release is not a draft or prerelease and contains exactly:
   DMG, ZIP, two blockmaps, `latest-mac.yml`, and `latest-mac.yml.sig`.

## Rollback

Before tag publication, revert the release-preparation commit. After a public
tag or Release exists, never rewrite it; fix any release defect in a new patch
version.

## Verification

- focused metadata, README, workflow, release signing, and preflight tests;
- `npm run stress:runtime`;
- full serial tests, build, verify, audit, and production smoke;
- exact local and remote tag-to-commit parity;
- successful release workflow;
- public six-asset digest and size verification.
